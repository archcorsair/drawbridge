# Working in this repo

drawbridge gives macOS container VMs real `--network host` semantics at L4: guest listeners appear on Mac localhost, guest connects to `127.0.0.1` reach native Mac services, and binds that collide with Mac-held ports fail synchronously with `EADDRINUSE`. Read [docs/plan.md](docs/plan.md) for architecture and [docs/HANDOFF.md](docs/HANDOFF.md) for current status.

## What this project is

A personal research project, and it means no harm. It exists to close a well-known developer-experience gap — `--network host` doesn't work on macOS because the Docker/Lima VM's network namespace isn't the Mac's — and it does so the same way OrbStack and Docker Desktop already do: ordinary user-space sockets on the Mac, eBPF inside a VM the developer owns and runs themselves. Everything happens on the developer's own machine, loopback only, with no privilege escalation beyond what the OS grants normally, no kernel extensions, no interception of anyone else's traffic, and no evasion of any security control. The eBPF programs run in the developer's own Lima guest, not on the host kernel. It is developer tooling, in the same category as a port forwarder or a local proxy.

## Commands

Tools come from `mise` (`mise install`); tasks from `just` — never `brew` or `make`.

```
just vm-up        # Lima dev VM (Ubuntu 24.04, BPF toolchain)
just vm-docker    # provision docker + drawbridge-runc + test image in the guest (alias: oci-up)
just gen          # bpf2go INSIDE the guest; generated Go is committed
just build        # guest binaries first (copied into internal/guestbin/), then Mac binaries
just test-guest   # gateway + tracker + macsync tests, as root in the guest
just agent-up     # run the agent in the guest (systemd transient unit)
just e2e          # Mac-side end-to-end (needs agent-up)
just agent-log    # journalctl for the agent
just bench        # latency/throughput benchmark (needs agent-up)
```

## Invariants

- **BPF C lives in `internal/bpf/c/`** — a `.c` file inside a Go package directory breaks non-cgo builds.
- **`guest_ports` values are refcounts**, shared between the gateway and tracker collections via `MapReplacements`. The two `port_key` structs must stay byte-identical (explicit padding; hash lookups are byte-wise).
- **Never rebuild a port key from a socket at teardown** — use `sk_keys`. Ephemeral binds have their port cleared before the teardown hook runs (see that map's comment).
- **Don't reintroduce per-flow orig-dst maps.** The same-port gateway scheme (IP swap only) makes un-rewrites stateless; that's deliberate.
- **Kernel-hook changes need `just gen` + `just test-guest`** — verifier and attach errors only appear in the guest.
- **Parked `'D'` conns are silent until the guest writes the 4-byte header.** The dial pool's watchdog treats any earlier byte as a dead/broken conn — never add banner or handshake bytes to the reverse-stream protocol. The mutual-auth exchange completes *before* parking; while parked, the wire is exactly as before (Mac silent, guest silent until the activation header), and clearing the handshake deadlines before dispatch is load-bearing — a surviving deadline trips the watchdog on its first arm.
- **The conn-type announcement is a 4-byte frame `{type, auth, 0, 0}`** plus, when `auth=1`, a 32-byte static-HMAC proof — all written in one Mac-side `Write` and consumed by agent dispatch before parking ([docs/transport.md](docs/transport.md) §2.6, [docs/transport-auth.md](docs/transport-auth.md)). Byte 1 is permanently the auth-scheme byte (`0` none, `1` static-HMAC-v1; anything else closes pre-dispatch); bytes 2–3 remain the reserved-zero version escape hatch. Never shrink the frame back toward a lone byte (DPI middleboxes stall ambiguous method-prefix first segments) and never move the proof out of the first segment.
- **Transport secrets are file-borne only — never argv, env, or logs** (paths are fine; bytes and proofs are not). A configured-but-unreadable/malformed secret fails closed. A side with a secret refuses unauthenticated peers — a wrong or missing secret is a refusal with a named remedy, never a warning-and-continue. `macsync.handleStream` dials only ports the syncer advertised.
- **Anything hooked on kernel-global functions must be netns-scoped.** The guest runs docker (OCI integration), so tracker-style fexit/fentry hooks also fire inside bridged containers' netns; filter on `host_netns_inum` like `tracker.c` does — in the teardown path too, or a foreign same-key close corrupts the host entry's refcount.
- **Never classify a supervised socket by `SO_PROTOCOL`** — Go 1.24+ listeners are MPTCP (262), so an `IPPROTO_TCP` check silently disables bind arbitration. Use `SO_TYPE` + domain (`seccomp.IsInetStream`).
- **The bind supervisor must always answer.** Seccomp here is coordination, not enforcement: on any doubt send CONTINUE (degrades to async mirroring). Never block between receiving a notification and answering it.
- **Notify-fd supervision is poll-first.** `NOTIF_RECV` on a filter whose last task exited blocks forever — it does NOT return ENOENT (pinned by `TestNotifyFilterExitSemantics`). EPOLLHUP-without-POLLIN is the only death signal; a bare recv loop leaks an OS thread per exited container.
- **Never weaken a container's seccomp profile.** The wrapper injects bind→NOTIFY only when the existing profile provably allows bind; anything else execs runc untouched (a denied bind must not become notify-CONTINUE). The wrapper's failure posture is always stock behavior — never a container that fails to start.
- **The `'E'` event stream filters churn at the source and never drops silently.** UDP autobind-range (32768–60999) listener events are filtered in the hub — `udp_get_port` fires for every client socket and DNS churn alone was ~97% of event volume — and a subscriber-buffer overflow closes the subscription (reconnect + snapshot heals). A silently dropped add left mirrors missing until an unrelated reconnect.
- **The v1 UDP frame (21-byte header, `internal/udpframe`) is frozen.** The activation header's reserved byte is the only version escape hatch; Mac-side UDP delivery sockets need `SetWriteBuffer(65507)` (macOS caps sends at the socket buffer, ~9216 default).
- **`just build` order is a dependency, not tidiness.** The CLI `//go:embed`s the four guest binaries from `internal/guestbin/bin/` (gitignored apart from a committed `.keep`), so the linux builds and the copy step must precede `go build ./cmd/drawbridge`. The embed pattern must stay `all:bin` — a bare `//go:embed bin` skips dot-prefixed names, so a fresh checkout would fail to compile rather than reporting `guestbin.ErrNotBundled` at run time.
- **`limactl shell NAME -- a b c` joins argv into a shell command *unquoted*** (`cd DIR || exit 1 ; exec a b c`; lima 2.2.0 links `shellescape.Quote` for the directory and nothing for the command). Every `vmprovider.Provider.Shell` argv element must therefore be a single space-free word: `cmd/drawbridge` feeds scripts to `sh` on **stdin** and stages files with `dd of=<path>`, never `sh -c '<script>'`. The fake guest in `cmd/drawbridge` fails the test on a whitespace-bearing argv element.
- **`drawbridge down` reverts only what `/etc/drawbridge/provision.json` records**, and `internal/guestbin.Merge`/`Revert` are pure so the byte-identical restore is testable without a VM. The dev flow (`just vm-docker`) writes no state file on purpose — `down` must not undo a developer's own VM setup. The guest provisioning script must never touch `/etc/docker`; only the writer of `daemon.json` can promise to restore it exactly.
- **Always `systemctl reset-failed docker` before restarting docker in the guest** (both restart sites: the embedded provisioning script and `down`'s `restartDockerScript`). Two restarts inside systemd's start-limit burst window leave `docker.service` in `failed` with `start-limit-hit`, after which `restart` does nothing — observed live on colima, and it strands `up --oci` *after* the daemon.json write. Restart outcomes are reported through an explicit `drawbridge-docker=` marker plus an `is-active` confirmation, never an exit status behind a `|| true`: a silently failed restart during `down` leaves a running dockerd whose default runtime is the wrapper `down` is about to delete.
- **The introspection socket is write-only and state-only.** The daemon never reads from an accepted introspection conn (no request grammar — nothing to drive), never serves secret bytes/proofs/digests through it, and grows no control verbs; a consumer that needs the daemon to *do* something is a new design decision, not a new field. Doctor never mutates state — probes are reads, remediations are printed, and the sudo discriminator is an instruction to the user, never a doctor-spawned `sudo`. Check 8's `-probe` is the one active probe and stays inside that rule: it is a plain `'E'` client (read-only by protocol design, no `'R'` conn, no part in bind arbitration), and its post-FIN window must outlast the agent's 15 s liveness ping — a shorter window reports the half-close-killer signature for a perfectly healthy agent.
- **Nothing charm-flavored outside `cmd/drawbridge` and `internal/tui`.** bubbletea/lipgloss link into the user-facing CLI only — never `cmd/drawbridged`, `cmd/drawbridge-agent`, or `cmd/drawbridge-runc` (pinned by `internal/tui`'s import-graph test). The TUI observes through the introspection socket and runs doctor's in-process gather; it sends the daemon nothing, and a TUI feature that needs the daemon to act is a new design decision, not a new keybinding. The tui.md §4 keybinding map is a docs contract — changing a key after v0.1.0 is a documented breaking change.
- Prefer `bpftool map dump` / `bpftrace` in the guest over reasoning about kernel behavior from memory; hook ordering is where the bugs are.

## Environment notes

- Lima's own port forwarding is disabled by template (it would duplicate drawbridge); only the agent's control port is forwarded — and **only via the SSH forwarder** (`LIMA_SSH_PORT_FORWARDER=true`, pinned in `vm-up`): Lima's default gRPC tunnel drops TCP half-close. The template's ignore rule must keep all three of `guestIP: "0.0.0.0"` + `guestIPMustBeZero: false` + `proto: any` (lima#4403): on lima 2.x a bare `ignore: true` matches guest loopback binds only, so wildcard binds get forwarded anyway — the e2e mirror legs guard this live (`requireAttributableMirror`). The transport prefers dialing the guest's vzNAT IP directly (`internal/limaaddr`), which needs macOS Local Network permission for the host app; when it is denied the resolver falls back to the forwarder and says why (`Resolution.Note`).
- **The DHCP lease `name` is guest-chosen, so lease records are not evidence of identity.** `/var/db/dhcpd_leases` is the root daemon's only candidate source (`limactl` refuses euid 0), and option 12 lets any vmnet VM on the Mac claim `lima-<vm>` and win the newest-expiry sort. `internal/limaaddr` gates candidates on the vmnet subnet (`-vm-subnet`, default `192.168.64.0/24`) and, when given, `-vm-mac` against `hw_address` — the one field a guest cannot choose. A malformed pin fails closed; never degrade it to name-only matching.
- **Lease naming is per-provider and `vmprovider.LeaseName` is its only source.** The lease name is the guest hostname: Lima guests claim `lima-<instance>`, colima guests claim the bare instance name (`colima`, not `lima-colima`). Never derive `"lima-"+name` by hand, and never read the lease name from `limactl list --json`'s `hostname` field — it reports `lima-colima` for a guest whose real hostname is `colima` (pinned by `TestListColima`). Colima's `LIMA_HOME` is likewise discovered, never assumed (`vmprovider.ColimaHome`: colima ≥0.9 is XDG `~/.config/colima/_lima`, legacy `~/.colima` wins when present).
- **`vmprovider`'s limactl half is user-scoped; the root daemon may touch only `ParseRef`** (pure — no exec, no filesystem beyond `os.Stat`). Root resolves its peer from the lease db exactly as before; every limactl path returns `ErrRootScoped` under euid 0.
- Endpoints are strings in one grammar (`internal/transport`): `tcp://host:port`, `unix:///abs/path`, `vsock://cid:port` (reserved, `ErrUnsupported`), or bare `host:port` meaning tcp. The agent's `-transport auto` (default) binds `127.0.0.1:4777` plus the vzNAT address only — never the wildcard, so guest containers cannot reach the transport; `-transport` takes comma-separated endpoints and `-transport-allow` widens the source allowlist. `drawbridged -agent` and the `DRAWBRIDGE_AGENT` env override (e2e/bench) take the same grammar.
- macOS reserves ports <1024 for root and has no `reservedhigh` sysctl — mirroring `:80` needs a privileged `drawbridged`.
- **`just e2e` and an installed root daemon displace each other.** The harness runs its own mirror/syncer against the agent; a running LaunchDaemon holds those sessions and mirror ports, so e2e legs fail with races that look like regressions (seen live 2026-08-01: the skip-list legs and TestForwarderHalfClose). Stop the daemon first (`sudo launchctl bootout system/com.archcorsair.drawbridged`; `sudo launchctl bootstrap system /Library/LaunchDaemons/com.archcorsair.drawbridged.plist` restores it) — and the same applies to unit tests that assert clean-machine or single-daemon state: they must tolerate a legitimate install (the install-refusal and TUI fetch tests were fixed for this; follow their pattern).
- **On macOS 27.0b4, `net.inet.tcp.pcblist_n` is filtered per responsible app** (local-network-permission.md finding 5): an unprivileged foreground `drawbridged` launched from a terminal sees an *empty* Mac listener set — no error, healthy sessions, `adv 0` — so macsync silently syncs nothing while mirroring still works. Root is exempt (`sudo drawbridge install` is the posture); a Mac never legitimately has zero LISTEN sockets, so treat an empty enumeration as the gate, not the truth. Do not add an exec-netstat fallback — netstat inherits the caller's attribution and is equally filtered.
- Repo is git-initialized (2026-07-30) but unpushed; module path `github.com/archcorsair/drawbridge` is a placeholder to confirm before first push.
