# drawbridge — session handoff

*Status only. Conventions live in [AGENTS.md](../AGENTS.md), architecture in [plan.md](plan.md), decisions/lessons in the ClawVault at `~/memory/drawbridge` (`clawvault context "<task>" --vault ~/memory/drawbridge`).*

## Where things stand (2026-07-30)

**All four roadmap phases are done and verified.**

- **Phase 1 — kernel loopback gateway: DONE.** 5/5 assertions green.
- **Phase 2 — listener tracking + inbound path: DONE (TCP).** Guest listeners mirrored onto Mac localhost. Netns-scoped since the OCI integration added in-guest docker: the kernel-global hooks compare the socket's netns inum against `host_netns_inum` (set by `LoadTracker` from its own netns), so bridged-container listeners never reach `guest_ports` or the Mac mirror (see plan.md "Tracker netns scoping").
- **Phase 3 — Mac listener sync + outbound path: DONE (TCP/IPv4).** A Mac loopback server is reachable inside the guest at the same `127.0.0.1:port`; sync-owned entries drop on session loss.
- **Phase 4 — synchronous `EADDRINUSE`: DONE (TCP).** A guest bind onto a Mac-held port fails synchronously with Linux `EADDRINUSE` via seccomp-unotify + reserve-before-ack; every uncertain path degrades to async behavior.
- **OCI integration: DONE (Docker/runc).** `docker run --network host` under the `drawbridge-runc` default runtime gets bind arbitration transparently (design: [oci-hook.md](oci-hook.md), results in plan.md): the wrapper injects `bind → SCMP_ACT_NOTIFY` + `listenerPath`, runc delivers the notify fd to the agent's OCI socket, bridged containers are skipped (wrapper) and backstopped (agent netns check). Guest provisioning: `just vm-docker` (idempotent; docker.io + wrapper + offline test image). Podman/crun reachable later via the identical contract.
- **UDP: DONE, both directions (design: [udp.md](udp.md), results in plan.md).** Guest UDP listeners are served on Mac localhost and Mac UDP services (explicit `drawbridged -udp PORT,PORT`) are reachable from the guest at `127.0.0.1:P` — muxed per-port framed streams over `'S'`/`'D'` proto 17, flow tables with idle expiry on the side that dials the real backend, zero BPF changes. Guest autobind-range (32768–60999) UDP is excluded from mirroring and from the event stream.
- **Benchmark: `just bench`** — TCP + UDP legs; numbers and findings in plan.md.

Suites: `just test-guest` (Phases 1–4 + OCI protocol + UDP sync in the VM), `just e2e` (eleven Mac-side flows incl. three real-container OCI tests, two UDP flows and two root-gated <1024 legs; container tests skip unless `just vm-docker` has run, the privileged legs unless run as root — `just e2e-root`), `go test ./internal/...` on the Mac, `just bench`.

Acceptance as an installed daemon covered all three <1024 flows: inbound (`docker run --network host nginx` → `curl localhost:80`), reverse (guest → Mac-native `:80`), and synchronous `EADDRINUSE` on a privileged port. The daemon is **uninstalled on this machine** (dev posture: foreground `drawbridged` + in-process e2e; an installed daemon and a foreground one fight over mirror ports, no single-instance lock by design). The demo can stop standardizing on `:8080`-class ports. **`:22` policy DECIDED (user, 2026-07-31): default skip-list + override.** Ship a small default exclusion (at minimum `:22`, the VM's sshd) with a flag to mirror anyway; skips are logged so they're discoverable. - **Transport: vsock reserved; vznat-direct shipped (phases 0–4); permission gate documented; phase 5 bench pending.** Design and phasing in [transport.md](transport.md). True AF_VSOCK is out for this iteration — Virtualization.framework scopes vsock to the VM-owning process, so only Lima's own driver can dial guest vsock ports (§1); `vsock://` parses as a reserved scheme and `Dial`/`Listen` return `ErrUnsupported`. What shipped: the 4-byte DPI-safe conn-type frame (Phase 0), the `internal/transport` endpoint seam — grammar `tcp://host:port | unix:///path | vsock://cid:port | bare host:port`, six dials and the agent listen behind it (Phase 1), the agent's scoped bind (`-transport auto` = loopback + vzNAT only, source allowlist, so guest containers can no longer reach the transport — Phase 2), the resolver's probe classification + live re-resolve on session reconnect (Phase 3), and the harness/bench/doc polish incl. `DRAWBRIDGE_AGENT` and `TestForwarderHalfClose` (Phase 4). The **macOS Local Network permission** gate is the one environmental dependency: granted here 2026-07-30 by subnet exemption ([notes/local-network-permission.md](notes/local-network-permission.md)), and when it is missing the resolver says so in words rather than falling back silently. The SSH-forwarded loopback (`LIMA_SSH_PORT_FORWARDER=true` pinned in `vm-up` — Lima's default gRPC tunnel **drops TCP half-close**) remains the fallback and keeps its own regression guard. **Phase 5 recorded 2026-07-30 (plan.md §Benchmark "Post-refactor"): latency-neutral vs the pre-refactor baseline; e2e 9/9; transport swap COMPLETE.**
- **vzNAT-direct baseline RECORDED (2026-07-30)** — plan.md §Benchmark "vzNAT-direct". Throughput ~6× (2.8–3.4 GB/s each way), burst flattened, inbound first-byte 0.35 ms, UDP halved; outbound first-byte *regressed* to 1.68 ms p50 (lone-small-packet latency on vzNAT — see the table's note). Getting it required diagnosing the Little Snitch 6.5 nightly's DPI, which stalls lone HTTP-method-prefix first bytes (drawbridge's `'D'`!) ~2 s per flow **even with the filter "disabled"** — only deactivating the network extension stops it (`docs/notes/local-network-permission.md` finding 3). If the user re-enables Little Snitch, bench numbers go invalid again; the transport-seam refactor should pad the conn-type byte so the protocol stops being DPI-bait. **Status end of 2026-07-30:** extension re-enabled (allow-all mode), hold re-confirmed present; unchecking Security → "Verify server names asserted by process" did NOT clear it (untested: extension restart after unchecking). Bug report emailed to obdev 2026-07-30; first reply 2026-07-31: they suspect the macOS Network Extension framework itself (behavior persisting with filter disabled) and will consult a developer colleague back the second week of August. Finding-4 follow-up (half-close) sent with the extension-deactivation + content-dependence datapoints. Check the thread before the next bench run. **Later 2026-07-30: second, distinct LS bug isolated — the extension breaks TCP half-close on non-loopback flows** (inbound bytes arriving after the app's `shutdown(SHUT_WR)` are kernel-ACKed but never delivered; `read()` starves indefinitely). This — not vzNAT FIN loss — was the bench `InboundThroughput` wedge; it repros with 1 byte, with no prior outbound traffic, and with plain direct TCP to the guest (no drawbridge at all). Full wire proof, standalone probe, and repro harness (`DRAWBRIDGE_WEDGE=1 go test -run TestWedgeRepro ./internal/bench/`) in `docs/notes/local-network-permission.md` finding 4. Send as an addendum to the obdev thread. Until fixed: the inbound-bulk bench leg needs the extension deactivated (or `DRAWBRIDGE_AGENT=tcp://127.0.0.1:4777`); no code workaround, deliberately.
- **Outbound first-byte optimization (deferred 2026-07-30, user-flagged).** Post-refactor outbound TCP first-byte is 1.67 ms p50 — a per-NEW-connection tax, not per-byte (warm streams cross in ~50–60 µs; UDP RTT rides warm muxed streams at 128 µs; inbound first-byte 0.31 ms). Cause: ~3 sequential *cold* small-packet Mac↔guest crossings at ~350–450 µs each (vmnet/virtio lone-packet delivery — same machinery as the batch-flush pattern in notes/local-network-permission.md). Levers, in order: (1) activation-header batching (transport.md §4 item 8, ~0.3–0.4 ms, touches gateway splice + needs a server-speaks-first timeout); (2) look for other cold-crossing eliminations in the activation sequence (e.g. dial-backend-before-header overlap); (3) the reserved vsock path skips vmnet entirely — the someday floor-breaker. Long-lived conns (Postgres/Redis) pay the tax once; per-request-conn workloads feel it.
