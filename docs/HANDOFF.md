**All four roadmap phases are done and verified.**

- **Phase 1 — kernel loopback gateway: DONE.** 5/5 assertions green.
- **Phase 2 — listener tracking + inbound path: DONE (TCP).** Guest listeners mirrored onto Mac localhost. Netns-scoped since the OCI integration added in-guest docker: the kernel-global hooks compare the socket's netns inum against `host_netns_inum` (set by `LoadTracker` from its own netns), so bridged-container listeners never reach `guest_ports` or the Mac mirror (see plan.md "Tracker netns scoping").
- **Phase 3 — Mac listener sync + outbound path: DONE (TCP/IPv4).** A Mac loopback server is reachable inside the guest at the same `127.0.0.1:port`; sync-owned entries drop on session loss.
- **Phase 4 — synchronous `EADDRINUSE`: DONE (TCP).** A guest bind onto a Mac-held port fails synchronously with Linux `EADDRINUSE` via seccomp-unotify + reserve-before-ack; every uncertain path degrades to async behavior.
- **OCI integration: DONE (Docker/runc).** `docker run --network host` under the `drawbridge-runc` default runtime gets bind arbitration transparently (design: [oci-hook.md](oci-hook.md), results in plan.md): the wrapper injects `bind → SCMP_ACT_NOTIFY` + `listenerPath`, runc delivers the notify fd to the agent's OCI socket, bridged containers are skipped (wrapper) and backstopped (agent netns check). Guest provisioning: `just vm-docker` (idempotent; docker.io + wrapper + offline test image). Podman/crun reachable later via the identical contract.
- **UDP: DONE, both directions (design: [udp.md](udp.md), results in plan.md).** Guest UDP listeners are served on Mac localhost and Mac UDP services (explicit `drawbridged -udp PORT,PORT`) are reachable from the guest at `127.0.0.1:P` — muxed per-port framed streams over `'S'`/`'D'` proto 17, flow tables with idle expiry on the side that dials the real backend, zero BPF changes. Guest autobind-range (32768–60999) UDP is excluded from mirroring and from the event stream.
- **Benchmark: `just bench`** — TCP + UDP legs; numbers and findings in plan.md.

Suites: `just test-guest` (Phases 1–4 + OCI protocol + UDP sync in the VM), `just e2e` (eleven Mac-side flows incl. three real-container OCI tests, two UDP flows and two root-gated <1024 legs; container tests skip unless `just vm-docker` has run, the privileged legs unless run as root — `just e2e-root`), `go test ./internal/...` on the Mac, `just bench`.

- **vzNAT-direct baseline RECORDED (2026-07-30)** — plan.md §Benchmark "vzNAT-direct". Throughput ~6× (2.8–3.4 GB/s each way), burst flattened, inbound first-byte 0.35 ms, UDP halved; outbound first-byte *regressed* to 1.68 ms p50 (lone-small-packet latency on vzNAT — see the table's note). Getting it required diagnosing the Little Snitch 6.5 nightly's DPI, which stalls lone HTTP-method-prefix first bytes (drawbridge's `'D'`!) ~2 s per flow **even with the filter "disabled"** — only deactivating the network extension stops it (`docs/notes/local-network-permission.md` finding 3). If the user re-enables Little Snitch, bench numbers go invalid again; the transport-seam refactor should pad the conn-type byte so the protocol stops being DPI-bait. **Thread RESOLVED 2026-08-13:** finding 3 is **intended DPI** (hostname classification; "disable filter" stops rule enforcement, not DPI — the shipped 4-byte frame is the vendor-recommended remedy), and finding 4 is a **vendor-confirmed bug**: aborting DPI on outbound close flips the socket to disconnected as a side effect, discarding post-close inbound delivery; **fix in the next Little Snitch release**, no vendor workaround (our DPI-exempt-port finding — >49152 half-closes cleanly, verified live 2026-08-12 — remains a de facto one, vendor-endorsed). Caveat: the vendor's own tests of the fix are inconsistent (intermittent residual failures, and Apple never invokes the API the fix targets), so Apple may have a similar NE-framework bug underneath. When the fixed LS release ships, re-run `TestWedgeRepro` at high iteration count, not once; persistent wedges under the fixed build become an Apple Feedback report. Details: local-network-permission.md findings 3/4 addenda. **Later 2026-07-30: second, distinct LS bug isolated — the extension breaks TCP half-close on non-loopback flows** (inbound bytes arriving after the app's `shutdown(SHUT_WR)` are kernel-ACKed but never delivered; `read()` starves indefinitely). This — not vzNAT FIN loss — was the bench `InboundThroughput` wedge; it repros with 1 byte, with no prior outbound traffic, and with plain direct TCP to the guest (no drawbridge at all). Full wire proof, standalone probe, and repro harness (`DRAWBRIDGE_WEDGE=1 go test -run TestWedgeRepro ./internal/bench/`) in `docs/notes/local-network-permission.md` finding 4 (sent to the obdev thread 2026-07-31; the 2026-08-12 port-exclusion addendum shows it follows the DPI exclusion list — >49152 half-closes cleanly). Until fixed: the inbound-bulk bench leg needs the extension deactivated, `DRAWBRIDGE_AGENT=tcp://127.0.0.1:4777`, or a DPI-exempt port; no code workaround, deliberately.
- **Outbound first-byte optimization (deferred 2026-07-30, user-flagged).** Post-refactor outbound TCP first-byte is 1.67 ms p50 — a per-NEW-connection tax, not per-byte (warm streams cross in ~50–60 µs; UDP RTT rides warm muxed streams at 128 µs; inbound first-byte 0.31 ms). Cause: ~3 sequential *cold* small-packet Mac↔guest crossings at ~350–450 µs each (vmnet/virtio lone-packet delivery — same machinery as the batch-flush pattern in notes/local-network-permission.md). Levers, in order: (1) activation-header batching (transport.md §4 item 8, ~0.3–0.4 ms, touches gateway splice + needs a server-speaks-first timeout); (2) look for other cold-crossing eliminations in the activation sequence (e.g. dial-backend-before-header overlap); (3) the reserved vsock path skips vmnet entirely — the someday floor-breaker. Long-lived conns (Postgres/Redis) pay the tax once; per-request-conn workloads feel it.

Background — the original statement of the goal:

**End-goal, user-prioritized (2026-07-31): adoption ergonomics for the open-stack (non-commercial-platform) audience.** Package drawbridge so a Lima/Colima/Podman-machine user gets it working in minutes without reading design notes. Likely shape (needs its own `/architect-then-build` design pass — none of this is committed): Homebrew formula / goreleaser release binaries; a `drawbridge up`-style bootstrap that detects the user's *existing* VM (colima, lima default template — not just the bespoke dev VM) and provisions the agent into it; `drawbridge doctor` covering the diagnosis knowledge earned here (route checks, Local Network permission, DPI middleboxes, endpoint resolution); a user-facing quickstart distinct from the dev workflow; Podman-machine + crun coverage folds in here (the OCI contract is already engine-neutral). Prereqs it will surface: public GitHub push (module path already confirmed), agent provisioning story for arbitrary BTF-kernel guests, and the `:22` exclusion policy — now decided: default skip-list + override (see the privileged-ports item).

Other directions, no forced order: IPv6 outbound, vsock transport swap (reserved), Mac UDP auto-discovery (U5), outbound first-byte latency levers (deferred, see open item), guest-infra port exclusion implementation (policy decided: default skip-list + override).
