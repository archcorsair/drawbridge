# Adoption ergonomics: packaging, `drawbridge up`, `drawbridge doctor`, release

Design note for the adoption-ergonomics direction (HANDOFF §Next,
user-prioritized 2026-07-31). Goal: a Lima/Colima/Podman-machine user gets
drawbridge working in minutes without reading design notes. This is
Mac-side CLI/packaging/docs work; **nothing under `internal/bpf/` changes,
no BPF map or key struct changes, no `just gen`**, and the wire protocol is
deliberately untouched (§6).

Companion docs: [plan.md](plan.md) (architecture),
[transport.md](transport.md) (endpoint grammar, resolver),
[privileged-daemon.md](privileged-daemon.md) (`internal/install`),
[oci-hook.md](oci-hook.md) (engine-neutral OCI contract),
[notes/local-network-permission.md](notes/local-network-permission.md)
(the diagnosis knowledge `doctor` encodes).

## 1. Shape of the proposal, in one screen

- **Distribution:** goreleaser on tag + a Homebrew tap generated by
  goreleaser. One Mac universal binary per command (`drawbridge`,
  `drawbridged`); the two guest binaries (`drawbridge-agent`,
  `drawbridge-runc`, static, linux/arm64 + linux/amd64) are **embedded in
  the `drawbridge` CLI via `go:embed`** — provisioning is offline and the
  provisioned agent version always equals the CLI version (lockstep by
  construction, §6).
- **`drawbridge up`:** attach-only bootstrap. Detects existing vz-backed
  VMs through a small provider abstraction (`internal/vmprovider`: Lima,
  Colima-as-Lima, Podman machine later), preflights the guest (BTF kernel,
  systemd, arch, vmType=vz), streams the embedded agent in over the
  provider's shell, installs a persistent systemd unit, optionally
  provisions the OCI runtime wrapper (`--oci`). Idempotent; re-run = 
  upgrade. It never creates a VM.
- **`drawbridge doctor`:** encodes every diagnosis this project has earned:
  provider/VM detection, guest prereqs, agent liveness + version match,
  endpoint resolution with the resolver's existing `Resolution.Note`
  classification, the vzNAT route-deletion pathology, macOS Local Network
  permission, DPI middlebox (Little Snitch-class NE filters), forwarder
  half-close, provider port-forwarding coexistence. Human output +
  `-json` for bug reports.
- **`:22` skip-list (decided policy, mechanism here):** Mac-side filter,
  default `{22}`, one `-skip` flag on `drawbridged` applied to **both**
  directions (guest→Mac mirroring and Mac→guest sync), skips logged,
  override by replacing the list. No wire change.
- **CI:** GitHub Actions. macOS job proves the Mac build + unit tests on a
  Go matrix {1.25.x, 1.26.x} (settles the untested go.mod floor); a Linux
  job cross-compiles the guest binaries and runs the root+BPF test suites
  directly on the runner kernel (GH `ubuntu-24.04` runners have BTF +
  cgroup v2 — real verifier coverage without a VM). `just e2e` stays a
  documented local release gate (no nested virtualization on GH macOS
  runners).
- **Sequencing:** security review → **user pushes** → CI → skip-list +
  version stamping → provider abstraction → `up` → `doctor` → docs +
  first release v0.1.0 → Podman/crun fast-follow.

### What this buys

The whole first-run experience becomes three commands and one sudo prompt:

```sh
brew install archcorsair/drawbridge/drawbridge
drawbridge up                 # finds your colima/lima VM, provisions the agent
sudo drawbridge install       # root daemon: :80 mirrors + TN3179-exempt transport
# or, unprivileged: drawbridged   (foreground, ports ≥1024)
```

with `drawbridge doctor` as the single answer to "it doesn't work".

### Alternatives rejected (and what would revive them)

| Alternative | Why rejected | What would revive it |
|---|---|---|
| `drawbridge up` creates VMs | drawbridge is a standalone component for the open stack (settled positioning); VM lifecycle belongs to Lima/Colima/Podman. Attach-only is also the cheaper-to-reverse contract — `--create` later is additive, un-shipping creation is not. | Clear demand for a zero-to-VM path that the providers themselves don't serve. |
| Guest agent downloaded at `up` time (GitHub release fetch) | Network dependency in the critical first-run path; version-skew surface (CLI vN fetching agent vM); supply-chain checksum plumbing for no benefit. | Embedded binaries pushing the CLI past what brew tolerates (they won't: ~20–25 MB uncompressed for both arches). |
| Separate brew artifact for guest binaries | Two installs to keep in lockstep; user-visible complexity for zero gain. | Never — dominated by embedding. |
| Wire version negotiation now (spend a reserved byte in the conn-type frame) | Current agents close conns with nonzero reserved bytes, so it isn't even backward compatible; a protocol byte, once given meaning, can never be taken back. Lockstep-by-construction + out-of-band version checks need no wire change. | A supported topology where CLI and agent legitimately ship separately (e.g. distro-packaged agent). §6. |
| `curl \| bash` installer | Brew is the audience's native idiom; a script installer adds an unauditable path for a tool that installs a root daemon. | Never as primary; maybe as a mirror later. |
| Auto-disabling the provider's own port forwarding | Requires template edits + VM restarts, and Lima 2.x has a known bug where disabling forwarding is broken (lima#4403). Too invasive for a bootstrap. | Providers exposing a supported runtime toggle. §5.3. |

## 2. Distribution and release engineering

### 2.1 Artifact matrix

| Artifact | GOOS/GOARCH | Notes |
|---|---|---|
| `drawbridge` (CLI) | darwin universal (arm64+amd64 lipo'd by goreleaser `universal_binaries`) | embeds all four guest binaries (§2.2) |
| `drawbridged` (daemon) | darwin universal | shipped in the same archive; `drawbridge install` copies it to `/usr/local/libexec` exactly as today |
| `drawbridge-agent` | linux/arm64, linux/amd64, `CGO_ENABLED=0` | embedded in the CLI; **also** attached to the GitHub release as standalone files (escape hatch for manual provisioning / non-brew users) |
| `drawbridge-runc` | linux/arm64, linux/amd64, `CGO_ENABLED=0` | same |

Intel Macs stay in: vz, vmnet, and `/var/db/dhcpd_leases` behave the same
there, and a universal binary costs one goreleaser stanza. The guest side
ships both arches because a vz VM's arch matches the host's — but Rosetta
guests and Intel hosts mean both appear in the wild, and `up` picks by
`uname -m` in the guest, not on the Mac.

### 2.2 Embedding: build ordering becomes a real dependency

`go:embed` needs the guest binaries to exist at CLI compile time. New
package `internal/guestbin` (darwin-only build tag) with
`//go:embed agent_linux_arm64 agent_linux_amd64 runc_linux_arm64 runc_linux_amd64`
and a `Binary(name, arch string) ([]byte, error)` accessor plus the
embedded systemd unit template and the provisioning script (§4.3).

Consequences to design around, not discover:

- `just build` gains ordering: guest binaries first, copied into
  `internal/guestbin/`, then Mac binaries. The copies are `.gitignore`d;
  a tiny committed placeholder + build tag keeps `go build ./...` and
  `go vet ./...` working on a fresh checkout (embed of a missing file is a
  compile error — use `//go:embed` on a directory with a committed
  `.keep`, and return a typed `ErrNotBundled` when the real binaries are
  absent so dev builds of the CLI still compile and `up` fails with
  "dev build without bundled agent — run `just build` first or pass
  `-agent-bin`").
- goreleaser: the CLI build hook runs the linux builds first (goreleaser
  `builds` ordering + a `prebuild` hook, or a `just release-prep` recipe
  invoked from `.goreleaser.yaml`).
- `-agent-bin path` override on `up` keeps the dev loop (freshly built
  agent without re-embedding) and is the escape hatch for the standalone
  release artifacts.

### 2.3 Homebrew

goreleaser's `brews` publisher maintains a formula in
`github.com/archcorsair/homebrew-drawbridge` (user creates the repo alongside the
main push). Formula installs `drawbridge` and `drawbridged` into brew's
prefix. No cask, no launchd management by brew: `drawbridge install`
remains the sanctioned root-daemon path (brew services would fight the
install machinery and can't render our plist).

`sudo drawbridge install` currently copies `drawbridged` from *beside the
invoking binary* (`resolveBinarySource`) — a brew Cellar path, which is
fine (both binaries live in the same `bin/`), but the security-review gate
(§8 Phase 0) should re-confirm `checkSecurePath` accepts brew's
`/opt/homebrew/bin` symlink chain and still rejects user-writable dirs the
way it was designed to.

### 2.4 Versioning

`const version` in `cmd/drawbridge/main.go` (0.0.2) is replaced by a shared
`internal/buildinfo` package populated via
`-ldflags -X github.com/archcorsair/drawbridge/internal/buildinfo.Version=...`
in all four binaries (justfile + goreleaser). The agent logs its version at
startup and writes `/run/drawbridge-agent.version`; `drawbridged` logs its
version at startup (the existing `status` log-tail already surfaces daemon
lines). This is the substrate for the §6 skew checks. Release tags are
`vX.Y.Z`; first public release v0.1.0.

## 3. Provider abstraction and endpoint generalization

### 3.1 The support matrix, stated honestly

| Provider | VM backend | Host→guest IP | Init | Default guest | v1 verdict |
|---|---|---|---|---|---|
| Lima (any instance, incl. `default`) | vz | vzNAT (`/var/db/dhcpd_leases`, name `lima-<vm>`) | systemd (Ubuntu default template) | Ubuntu LTS — BTF ✓ | **Supported** |
| Colima | Lima under a discovered `LIMA_HOME` (instance `colima` / `colima-<profile>`; ≥0.9 is XDG — see Phase 3 results) | same, lease **`colima`** (bare instance name — amended in Phase 3; the guest hostname, not `lima-<…>`) | systemd (Ubuntu) | Ubuntu — BTF ✓ | **Supported** (vz vmType only) |
| Lima/Colima with `vmType: qemu` | qemu | none (user-mode slirp; no host-reachable IP, no lease record) | — | — | **Rejected with doctor message** ("switch to vz: `colima start --vm-type vz` / lima `vmType: vz`") |
| Colima legacy Alpine image | vz | vzNAT | OpenRC, no systemd | Alpine | **Rejected with doctor message** (systemd required in v1; §9 Q6) |
| Podman machine | applehv/vfkit or libkrun, networking via **gvproxy** (user-mode) | none directly; gvproxy can expose forwards via its control API | systemd (Fedora CoreOS) — BTF ✓ | FCOS | **Fast-follow** (Phase 7; transport needs its own spike, §7) |
| Bespoke dev VM | vz | vzNAT + template-forwarded :4777 | systemd | Ubuntu 24.04 | Supported (unchanged; `just agent-up` remains the dev loop) |

The load-bearing constraint: **the shipped transport requires a
host-dialable guest IP (vzNAT) or a pre-existing loopback forward of
:4777.** Foreign Lima/Colima VMs have vzNAT but do *not* forward 4777, so
for them **vzNAT-direct is the only path in v1** — which is exactly what
the root LaunchDaemon posture makes reliable (TN3179 exemption), and what
`doctor` diagnoses when it isn't (unprivileged + permission denied).
A drawbridged-managed `ssh -N -L` fallback tunnel (built from
`limactl show-ssh`-style config) is the designed contingency if
vzNAT-direct proves too fragile in the field — deliberately *not* built in
v1; it only works unprivileged (root has no user SSH keys) and adds a
process-supervision surface. Cheap to add later behind the existing
resolver seam.

### 3.2 `internal/vmprovider` (new)

```go
type Instance struct {
    Provider  string // "lima" | "colima" | "podman"
    Name      string // provider-scoped instance name
    VMType    string // "vz" | "qemu" | ...
    LeaseName string // dhcpd_leases match, e.g. "lima-colima"
    Running   bool
}
type Provider interface {
    List() ([]Instance, error)                  // shells out to limactl/colima/podman, user-scoped
    Shell(inst string, stdin io.Reader, argv ...string) ([]byte, error)
    GuestArch(inst string) (string, error)      // uname -m via Shell
}
```

- **Lima:** `limactl list --json`. Colima is the same implementation with
  colima's own `LIMA_HOME` — *discovered, not assumed* (`vmprovider.ColimaHome`;
  amended in Phase 3: colima ≥0.9 is XDG, `~/.config/colima/_lima`, and the
  legacy `~/.colima` wins when it exists) — and the `colima*` instance
  names; detect both homes, tag the provider name for UX. This inherits the existing
  invariant for free: *`limactl` refuses euid 0*, so `List`/`Shell` are
  user-side only. The root daemon never touches vmprovider — it keeps
  resolving via the leases file exactly as today.
- **Podman:** Phase 7. `podman machine list --format json`, shell via
  `podman machine ssh`.

### 3.3 `internal/limaaddr` generalization (rename in place, no move)

Today `Resolve(vmName, port)` hardcodes lease name `lima-<vm>` and the
`limactl shell` candidate source. Change: `Resolve` gains the lease name as
an explicit parameter (or a small `Target{VMName, LeaseName, LimaHome}`
struct), with the current behavior as the compatibility default.
`drawbridged` gets `-vm` extended to accept `provider:name`
(`colima:default`, `lima:myvm`; bare name keeps today's meaning), maps it
to a `Target` at startup, and renders the same form into the install plist
(`drawbridge install -vm colima:default`). The resolver's probe, ordering,
classification, and `Resolution.Note` text are untouched — they are the
part `doctor` reuses.

The package keeps its name (it *is* Lima-addressing, and Colima is Lima);
Podman gets its own resolution source in Phase 7 rather than contorting
this one.

### 3.4 Coexistence with the provider's own port forwarding

An end user's Lima/Colima VM runs Lima's port forwarder, which watches
guest listeners and forwards them to Mac localhost — the same ports
drawbridge mirrors. Posture, decided here: **coexist and warn, never
auto-disable.**

- Mirror binds that lose the race get `EADDRINUSE`, hit the existing
  `logBindError` log-and-skip path, and the guest listener is still
  reachable on Mac localhost — via the provider's forwarder. Degraded
  (no synchronous bind arbitration semantics on that port's Mac side,
  slower path), but *working*, which is the right first-run experience.
- The reverse path (guest→Mac `127.0.0.1`) and bind arbitration
  (`EADDRINUSE` inside the guest) don't overlap with the forwarder at all
  and work fully.
- `doctor` detects an active provider forwarder (Lima: the instance's
  `portForwards`/`ssh.forwardAgent` config + the hostagent process) and
  prints the honest tradeoff plus the opt-in instructions for full
  semantics (template `portForwards: ignore` edit — with the warning that
  lima 2.x has a known disable bug, lima#4403, so verify after restart).
- `up` prints a one-line version of the same warning when it detects this.

Rejected: requiring forwarding off (turns a 3-command quickstart into a
template-editing session); auto-editing the template (invasive, restart
required, known-buggy toggle upstream).

## 4. `drawbridge up` (and `down`)

### 4.1 Contract

`drawbridge up [instance] [flags]` — user-mode, no sudo. Idempotent.
Attach-only: if no candidate VM exists, print the provider-specific
creation one-liners and exit 1; never create.

Steps:

1. **Discover.** Enumerate providers; zero running vz instances → the
   "how to create one" message. One → use it. Several → list and require
   the instance argument (no interactive prompt; scriptable).
2. **Preflight** (all via `Provider.Shell`, each failure is a doctor-grade
   message, not a stack trace):
   `uname -m` (pick embedded arch); `test -r /sys/kernel/btf/vmlinux`
   (BTF); `test -d /sys/fs/cgroup/cgroup.controllers` (cgroup v2);
   `command -v systemctl` (systemd; §9 Q6); kernel ≥ 5.7 for the seccomp
   listenerPath contract (`uname -r` parse — informational unless `--oci`).
3. **Push the agent.** Stream the embedded binary over the provider shell
   (`cat > /tmp/… && sudo install -m 0755 -o root /tmp/… /usr/local/bin/drawbridge-agent`).
   Compare a sha256 first; skip the copy when current (fast idempotent
   re-run).
4. **Install the unit.** Render the embedded
   `drawbridge-agent.service` (plain persistent unit:
   `ExecStart=/usr/local/bin/drawbridge-agent`, `Restart=on-failure`,
   `WantedBy=multi-user.target`) to `/etc/systemd/system/`, then
   `systemctl daemon-reload && systemctl enable --now`. On binary change:
   `systemctl restart`. The dev VM's transient-unit flow (`just agent-up`)
   is unchanged and documented as the dev override (a transient unit and
   the persistent one would fight; `up` stops the transient unit if
   present).
5. **`--oci` (optional, default off in v1):** additionally push
   `drawbridge-runc` and run the embedded, generalized
   `provision-docker.sh` logic (wrapper copy + `daemon.json` merge +
   conditional docker restart — the script is already idempotent and
   engine-scoped; it moves into `internal/guestbin` as an embedded asset,
   with the repo copy kept for the dev flow until Phase 7 unifies them).
   Default off because editing a user's `daemon.json` and setting
   `default-runtime` deserves an explicit opt-in; without it, inbound
   mirroring/outbound/EADDRINUSE-for-host-processes all still work — only
   containerized bind arbitration needs the wrapper.
6. **Verify + hand off.** Dial the transport (reuse
   `limaaddr.Resolve` + probe), print endpoint, source, agent version, and
   exactly one next step: `sudo drawbridge install -vm <provider:name>`
   (or "run `drawbridged -vm <provider:name>` for an unprivileged
   foreground session").

`drawbridge down [instance]`: `systemctl disable --now`, remove unit +
binaries, revert the `daemon.json` merge if `--oci` had applied it
(remove the `drawbridge` runtime key; restore `default-runtime` only if we
set it — record what we changed in a small state file in the guest,
`/etc/drawbridge/provision.json`, so revert is exact, never a guess).

### 4.2 Failure posture

Mirrors the runc wrapper's rule: **the failure posture is always "nothing
changed."** Every guest mutation is preceded by its preflight; a failed
step prints the doctor-grade diagnosis and leaves prior state (the unit
install is the last mutating step before verify). No partial daemon.json
writes (same merge-then-compare-then-write pattern the script already
uses).

### 4.3 Affected files (Phase 4)

- `internal/guestbin/` (new): embeds, unit template, provision script,
  `ErrNotBundled`.
- `internal/vmprovider/` (new, from Phase 3).
- `cmd/drawbridge/up.go`, `down.go` (new verbs; `main.go` dispatch).
- `justfile`: `build` reordering + copy step (§2.2).
- `scripts/provision-docker.sh`: factored so the embedded asset and the
  dev recipe share one source.

## 5. `drawbridge doctor`

One verb, ordered checks, each `ok | warn | fail` + a one-line remediation;
`-json` emits the full structured report for bug filing. Checks are pure
functions over injected probe results wherever possible (unit-testable
without a VM — same discipline as the install machinery's decision
tables). The knowledge encoded, with its provenance:

| # | Check | Source of the knowledge |
|---|---|---|
| 1 | Providers present + running vz instances; qemu instances flagged with the vz switch instruction | §3.1 matrix |
| 2 | Guest prereqs: BTF, cgroup v2, systemd, kernel ≥5.7, runc ≥1.1.0/crun (when `--oci`/wrapper present) | oci-hook.md; dev-VM template |
| 3 | Agent: unit active, `/run/drawbridge-agent.version` vs CLI version, transport listening (`ss` via provider shell) | §6 |
| 4 | Endpoint resolution: run `limaaddr.Resolve`, print `Endpoint`/`Source`/`Note` verbatim — the probe classification (EHOSTUNREACH→Local Network denial, ECONNREFUSED→agent not listening, no-guest-IP) already is the diagnosis text | transport.md §2.2 |
| 5 | vzNAT route: `192.168.64.0/24` route present + ARP entry; missing → the Tailscale/Little Snitch route-deletion pathology and the exact `sudo route -n add -net 192.168.64.0/24 192.168.64.1` remediation | local-network-permission.md finding 1 |
| 6 | Local Network permission: unprivileged probe failed but root path viable → explain TN3179 exemption ("`sudo drawbridge install` sidesteps this") + Settings path + subnet-exemption `defaults write` fallback | local-network-permission.md findings 2/4 |
| 7 | DPI middlebox, passive: `systemextensionsctl list` for content-filter NE extensions; when present, warn that Little Snitch-class filters have been observed stalling flows and breaking TCP half-close **even when disabled** (obdev thread ongoing, NE-framework suspicion), and that bench numbers are invalid while active | local-network-permission.md finding 3; HANDOFF open item |
| 8 | Half-close probe, active (opt-in `-probe`): against the resolved endpoint, run the `TestForwarderHalfClose`-shaped exchange; a stall/EOF anomaly names the forwarder or an NE filter | transport.md Phase 4 |
| 9 | Daemon: `install` state via `install.Query()`, version match CLI↔installed `drawbridged` (`/usr/local/libexec/drawbridged -version`), log tail | privileged-daemon.md §3.2 |
| 10 | Provider-forwarder coexistence: hostagent forwarding active → the §3.4 tradeoff paragraph | §3.4 |
| 11 | Skip-list visibility: parse recent skip log lines ("guest :22 skipped") so the default exclusion is discoverable exactly where a confused user will look | §7 policy ":skips are logged" |

No active DPI *timing* probe in v1 (the 4-byte frame made our own protocol
DPI-safe; a synthetic ambiguous-prefix probe would be re-deriving finding 3
on the user's machine for marginal value). Passive detection + the
half-close probe cover the field cases.

Files: `cmd/drawbridge/doctor.go`, `internal/doctor/` (check functions +
report types, pure parts unit-tested), small additions to
`internal/install` (expose version of installed binary) — no changes to
resolver logic.

## 6. Version skew policy

First release creates the first CLI↔agent skew surface. Policy:
**lockstep by construction, verified out-of-band, wire untouched.**

- Embedding (§2.2) means `up` always provisions the agent matching the
  CLI. The remaining windows: brew upgraded but `up` not re-run (stale
  agent in guest), and brew upgraded but `install` not re-run (stale
  daemon on Mac).
- Both are closed by detection, not negotiation: agent version file +
  daemon `-version` (§2.4), compared by `doctor` (fail) and by `up`
  (auto-heals the guest side by re-pushing). `status` gains the daemon
  version line. Brew's caveats text says: after upgrade, run
  `drawbridge up && sudo drawbridge install`.
- **The wire stays exactly as shipped.** The conn-type frame's three
  reserved zero bytes, the `'S'`/`'D'` activation headers, and the frozen
  v1 UDP frame are not touched; their existing strict-zero validation *is*
  the version policy — an incompatible future peer fails closed (conn
  closed on nonzero reserved) instead of misdispatching. We spend a
  reserved byte only when a topology ships where CLI and agent genuinely
  version independently; nothing in this design creates one.
- Invariants honored explicitly: parked `'D'` conns stay silent until the
  guest's 4-byte header (no hello added anywhere); the 4-byte type frame
  is never shrunk; UDP frame frozen.

## 7. `:22` skip-list (mechanism; policy already decided)

Decided (user, 2026-07-31): default skip-list + override; skips logged.
Mechanism:

- **Both directions, one flag.** `drawbridged -skip "22"` (default).
  - Mirror direction (guest listener → Mac): filter 'E' events in
    `internal/mirror` before binding; log
    `mirror: skipping guest :22 (default skip-list; -skip= to override)`.
    Filtering Mac-side means the event stream itself is untouched — no
    interaction with the hub's UDP-churn filtering, and **no silent
    drops**: the skip is a logged, deliberate decision at the consumer,
    which respects the "'E' stream never drops silently" invariant
    (the stream delivered it; the mirror declined it, audibly).
  - Sync direction (Mac listener → guest): add the ports to
    `macsync.Syncer.Exclude` (the seam already exists — agent port and
    mirror self-ports are excluded there today). This is the direction
    where `:22` is genuinely dangerous: syncing the Mac's Remote Login
    into `mac_ports` would steer in-guest `ssh localhost` to the Mac's
    sshd.
- **Override:** `-skip ""` disables entirely; `-skip "22,5353"` replaces.
  A port removed from the default list simply mirrors/syncs normally —
  no allow-flag needed, replacing the list *is* the override.
- **Install passthrough:** `drawbridge install -skip …` renders into the
  plist like `-udp` does.
- **Default list content: `22` only.** The agent transport port is already
  excluded structurally; UDP autobind churn is already handled at the hub.
  Growing the default list is a one-line change once field evidence
  arrives; shipping a long speculative list is not reversible cheaply
  (users will depend on entries).

No agent/BPF involvement: the guest tracker still tracks `:22` (refcounts
in `guest_ports` are untouched — that map is gateway/tracker state, not
mirror policy), so flipping the flag needs no guest restart. Files:
`internal/mirror/mirror.go`, `internal/macsync/sync.go` (tiny),
`cmd/drawbridged/main.go`, `internal/install` plist args,
`internal/e2e` new legs.

## 8. Phases

Model: each independently landable, system working after each. The
**user performs every git push and tag push** — phases prepare, verify,
and hand over.

### Phase 0 — pre-push gate

Security review of the flagged surfaces (install machinery — including
§2.3's brew-path check, transport bind scope, leases parser) via the
`security-review` skill; fix findings. Version stamping via
`internal/buildinfo` + ldflags in justfile (all four binaries), agent
writes `/run/drawbridge-agent.version`. Confirm module path
`github.com/archcorsair/drawbridge` and LICENSE presence. **User pushes
`main` to the public repo and creates `archcorsair/homebrew-drawbridge`.**

*Verify:* `go test ./internal/...` (Mac), `just test-guest`,
`just agent-up && just e2e` — all green with stamped versions visible in
logs (`agent-log` shows version line).

#### Phase 0 results (2026-07-31)

**Version stamping: DONE.** `internal/buildinfo.Version`, ldflags in
`just build`, `drawbridge version` / `drawbridged -version`, agent logs
its version and writes `/run/drawbridge-agent.version`. The runc wrapper
is deliberately unstamped — it owns no argv/stdio surface beyond exec'ing
the real runtime, and inventing one to print a version would put the
wrapper's "nothing changed" failure posture at risk for a diagnostic.

**Security review: DONE, one finding fixed, one refuted.**

*Finding (fixed, `e2b361f`) — lease-name squatting selects the root
daemon's peer.* The DHCP `name` in `/var/db/dhcpd_leases` is option 12,
the guest's own choice, and `hw_address` was parsed but never read. The
root LaunchDaemon renders `-agent auto` (pinning deliberately avoided so
live re-resolve works) and `limactl` refuses euid 0, so the lease db is
its **only** candidate source. Any vmnet-attached VM on the same Mac
could claim `lima-<vm>`, win the newest-expiry sort — four squatted
leases evict the genuine record past `maxLeaseCandidates` entirely — and
become the daemon's trusted peer, which then drives root loopback binds
(including <1024) and, via `macsync.handleStream`, root dials to
arbitrary `127.0.0.1:<port>`. This is additive over the accepted risk in
[privileged-daemon.md](privileged-daemon.md), which bounds guest
compromise with "the guest is the developer's own VM" — precisely the
bound name-only matching voids. **It also matters more after this
work, not less: the whole point of `up` is a Mac running the user's own
Colima/Lima/Podman VMs alongside anything else they boot.** Fixed with
two gates ahead of the sort — vmnet subnet (`-vm-subnet`, default
`192.168.64.0/24`) and, when given, `-vm-mac` against `hw_address`, the
one field a guest cannot choose. Malformed pin fails closed. Refusals
surface on `Resolution.Note`; the unpinned case warns once per process.

*Refuted — `sudo drawbridge install` copying an unverified source
binary.* `resolveBinarySource` takes the sibling of the running CLI, so
"can write `drawbridged`" is by construction "can write the binary about
to run under sudo" — the attacker already has root execution, which
subsumes installing a daemon. Not additive. Destination machinery
verified sound (`checkSecurePath` walk, `writeRootFile` temp+chown+
chmod+rename, `vmNameRE` allowlist — no plist injection).

**§2.3's brew question, answered — and its premise was wrong.**
`checkSecurePath` would **reject** every Homebrew install, not accept it:
`/opt/homebrew` is user-owned and `/opt/homebrew/bin` is group-writable,
tripping both `secureDirInfo` conditions. So §2.3's "re-confirm it
accepts brew's symlink chain" cannot be satisfied as written. Since the
finding it guards against is refuted, **do not add the source-path check**
— the durable answer is code-signature verification once releases are
signed. Trust assumption to state in the docs: whatever can write next to
the CLI owns the root daemon.

**Open, deliberately not built: transport authentication.** Both the
lease fix and the `handleStream` "dial any Mac loopback port" primitive
are symptoms of an unauthenticated transport — any future resolution
source is one impersonation away from the same outcome. A per-install
secret provisioned into the guest alongside the agent is the durable fix,
and `up` (Phase 4) is the natural place to provision it. Deferred as its
own decision: see Q8.

**Follow-ups carried:** `launchctl` is invoked by bare name in

**First interactive pass (2026-08-01) — the `adv 0` incident.** The
user's TTY run surfaced, within seconds of the TUI existing, a state no
headless check had caught: a healthy daemon (session up, pool parked 8,
mirror up) advertising *nothing*. The root cause, proven by the
discriminator ladder, was **not a drawbridge bug**: macOS 27.0b4
filters `net.inet.tcp.pcblist_n` per responsible app
(local-network-permission.md finding 5) — the identical binary saw the
full LISTEN set under one app context and zero, immediately and
persistently, under ghostty *and* Apple Terminal; Apple's own `netstat`
run from a terminal was equally filtered (attribution follows the
responsible app, so an exec-netstat fallback is ruled out); root was
exempt, proven live, and `sudo drawbridge install` restored sync on the
spot. Every terminal-launched foreground daemon had been sync-blind
*from birth* — there was never an aging effect, and the first "torn
read heals it" reading of the incident was wrong.

The investigation still found a real adjacent defect, fixed and pinned
by synthetic fixtures: `parsePcblistN` accepted a buffer missing its
trailing xinpgen (the `SysctlRaw` size-then-read race) as a
complete-looking smaller result. The parser now errors on a missing
trailer (header-only `n == 0` stays legitimate-empty — the header count
discriminates), `Listeners` retries a torn read ×3 then surfaces the
error so a persistent tear restarts the session visibly, and the
non-empty→empty advertised transition logs one throttled line and
rings `advertised-emptied`. Because the *gate* shape never makes that
transition, a session established advertising nothing gets its own
alarm — `advertised-none`, once per session, naming finding 5 and the
exempt posture — and doctor's daemon section states the anomaly
directly from the snapshot (a Mac never legitimately has zero LISTEN
sockets), ring or no ring. The incident now has a name at the daemon,
in the ring, in doctor, and in the TUI's refusals pane.

## 9. Open questions for the user, ranked by plan impact

**Q1 — Guest binary delivery: embed in the CLI?**
Options: (a) **embed both linux arches via go:embed — recommended**
(offline `up`, lockstep by construction, ~20–25 MB binary cost);
(b) download from GitHub releases at `up` time (small CLI, but network +
checksum + skew surface in the critical path); (c) separate brew artifact
(two installs to keep aligned).
*Impact:* shapes Phase 4's core mechanism, the justfile/goreleaser build
ordering, and the §6 skew posture. Everything downstream assumes (a).

**Q2 — Provider port-forwarding coexistence posture.**
Options: (a) **coexist + warn (doctor/up), document the opt-out —
recommended** (works out of the box, degraded arbitration on contested
ports); (b) require forwarding disabled before `up` proceeds (full
semantics, hostile first-run, upstream disable bug lima#4403);
(c) auto-edit the template with consent (invasive, restart, same bug).
*Impact:* Phase 4's preflight severity and the quickstart's honesty
paragraph; reversible later, but the first release's field reports will
be shaped by it.

**Q3 — First release scope.**
Options: (a) **v0.1.0 after Phase 6 (up + doctor + quickstart) —
recommended**: the release *is* the ergonomics claim; (b) an earlier
v0.0.x right after CI (install/status only) to shake out goreleaser/tap
plumbing with zero audience. A quiet (b) then (a) is cheap if the tap
being briefly boring is acceptable.
*Impact:* ordering of Phase 6 work only.

**Q4 — `--oci` default in `up`.**
Options: (a) **opt-in flag, default off — recommended** (editing
`daemon.json` + `default-runtime` on a user's engine deserves explicit
consent; core mirroring works without it); (b) default on with a
`--no-oci` opt-out (the headline demo `docker run --network host` gets
bind arbitration out of the box, at the cost of silently reconfiguring
docker).
*Impact:* Phase 4 UX + quickstart text; one flag default, trivially
reversible, but (b)→(a) breaks users who relied on it.

**Q5 — Go floor.**
Options: (a) **keep 1.25.0 if the CI matrix proves it — recommended**
(floor becomes tested truth); (b) bump to 1.26 now and drop the matrix
row (simpler CI, excludes packagers on n-1).
*Impact:* Phase 1 matrix only; the phase's decision rule handles it
either way.

**Q6 — Non-systemd guests (Alpine/OpenRC Colima).**
Options: (a) **documented rejection with a doctor message — recommended**
(v1 matrix stays honest and small); (b) OpenRC unit support in `up`
(second init-system template + testing surface for a shrinking audience —
current Colima defaults to Ubuntu).
*Impact:* Phase 4 preflight only; additive later.

**Q7 — Podman sequencing.**
Options: (a) **fast-follow after v0.1.0 (Phase 7) — recommended**: the
gvproxy transport spike is genuinely open-ended and must not gate the
Lima/Colima release; (b) in-scope for v0.1.0 (release blocks on the
spike).
*Impact:* whether Phase 7 precedes Phase 6.

**Q8 — Transport authentication (added by the Phase 0 security review).**
The Mac↔guest transport authenticates nobody: whoever answers the probe
first becomes the root daemon's trusted peer, and `macsync.handleStream`
will then dial *any* `127.0.0.1:<port>` the peer names, synced or not.
The lease pin closes today's impersonation route; it does not make the
transport authenticated.
Options: (a) **provision a per-install shared secret into the guest
during `up` and check it in the conn-type frame exchange — recommended,
scheduled as Phase 4.5** (natural fit: `up` is already writing files into
the guest, and it lands before the first public release rather than
after); (b) defer past v0.1.0, relying on the lease pin plus the
loopback-only posture; (c) narrower and cheaper: bound `handleStream` to
ports the syncer actually advertised, which caps any future peer-confusion
bug at the ports the Mac deliberately offered — worth doing regardless of
(a) or (b).
*Impact:* adds a phase and touches the transport handshake — the one
place in this plan that would otherwise leave the wire untouched (§6).
Note (c) is independent and cheap; (a) vs (b) is the real question.

**RATIFIED (user, 2026-07-31): (a) — per-install secret, provisioned by
`up`, verified in the conn-type frame exchange, as Phase 4.5 before
v0.1.0; (c) lands with it regardless.** Rationale accepted: pre-release
is when the wire change is free (embedded agents update in lockstep; no
released artifact to stay compatible with), and the same-day wrong-VM
fallback attach was the live demonstration of trust-by-first-answer.
Phase 4.5 needs its own design note before building — it touches the
conn-type frame, which is frozen-shape territory (AGENTS.md invariant:
the 4-byte frame with three zero reserved bytes; current agents close
conns with nonzero reserved bytes, so the escape hatch design must not
assume backward compatibility).
