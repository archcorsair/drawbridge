## Upgrading

```sh
brew upgrade archcorsair/drawbridge/drawbridge
drawbridge up <vm>          # re-pushes the agent, and the --oci runtime wrapper if the guest has one
sudo drawbridge install     # no flags: keeps the installed daemon's VM and settings
```

The guest agent, the runtime wrapper and the installed daemon are all copies,
so the second and third commands are not optional after a cask upgrade;
`drawbridge doctor` reports the skew if you skip them. Two of them behave
differently from v0.2.0, and one upgrade step has a one-time cost on `--oci`
guests.

**A plain `drawbridge up <vm>` now refreshes the `--oci` runtime wrapper.**
In v0.2.0 `up` pushed the wrapper only under `--oci`, so the documented
upgrade left an `--oci` guest on the old wrapper, and the wrapper fix in this
release (below) would never have reached it. `up` now replaces an installed
wrapper whose digest differs from this build's, using the same
install-then-rename as `--oci`, and prints either `refreshed <path>` or
`<path> already current`. It never installs a wrapper that is not there,
never writes `daemon.json`, the podman drop-in or `provision.json`, and never
restarts docker or podman: both exec the wrapper's path per container, so
the next container runs the new one.

**A bare `sudo drawbridge install` keeps the installed daemon's VM.** In
v0.2.0 `-vm` defaulted to `drawbridge`, so a flagless re-install pointed a
colima or podman daemon at `lima:drawbridge` and dropped `-vm-mac`,
`-vm-subnet`, `-udp` and `-skip`. Now every flag you do not pass comes from
the installed plist, and install prints each one it kept
(`keeping -vm colima:colima from the installed daemon`). An explicit flag
wins, including `""`. `-vm-subnet`, `-udp` and `-skip` apply Mac-wide and carry
over to a new VM. `-vm-mac` and `-secret-file` belong to one VM, so they are
kept only for the same VM and otherwise derived as a fresh install would,
with a note saying so. `install -print` shows the merged result. install now
also takes the VM positionally, like `up` and `down`, and install, uninstall,
status, doctor and tui exit 2 on a leftover argument instead of silently
ignoring it and every flag after it.

**On an `--oci` guest, the first agent restart drops running containers'
listeners.** From this release on, the agent parks each host-network
container's seccomp notify fd in systemd's fd store and takes it back after
a restart or crash, so a running container's `bind()` keeps working. The
v0.2.0 agent stored nothing. When `drawbridge up` restarts it onto this
release, the old agent's copies close with it, and they were the only
references. Every `--network host` container that was started under the
wrapper before the upgrade then gets `ENOSYS` (`Function not implemented`)
from `bind()` for the rest of its life. Restart those containers after `up`,
or stop them before it. Guests not provisioned with `--oci` are not affected.
A full stop (`drawbridge down`, `systemctl stop`) still releases the store by
systemd's own rule; see
[docs/oci-hook.md](https://github.com/archcorsair/drawbridge/blob/main/docs/oci-hook.md#agent-restarts-and-running-containers).

## Fixes from the 2026-10-18 audit

Recommended for every user with bridged containers, because of the first
item alone. Details:
[docs/security-audit-2026-10-18.md](https://github.com/archcorsair/drawbridge/blob/main/docs/security-audit-2026-10-18.md).

- **Loopback inside a bridged container works again on Mac-held ports.** The
  loopback gateway's BPF hooks attach at the root cgroup, so they also ran
  for bridged containers. A container's connect to its own `127.0.0.1:P` was
  rewritten whenever the Mac held `P`, and failed with `ECONNREFUSED`. The
  hooks now act only in the guest's own network namespace, matched by its
  `SO_NETNS_COOKIE`. That is also why the kernel floor below exists.
- **Agent restarts and crashes no longer break `bind()` in running
  containers**, through the fd store described under Upgrading.
- **The wrapper never rewires a seccomp profile that already has an agent.**
  A profile with its own `listenerPath` or any `SCMP_ACT_NOTIFY` rule used to
  get drawbridge's listener in its place, so a notify-based deny policy
  became allow. Such a profile now runs untouched. The supervisor also checks
  `bind` per ABI, so a 32-bit container on a 64-bit guest gets its
  synchronous `EADDRINUSE` again.
- **Handoff and accept-loop hardening.** The agent refuses a handed-over fd
  that is not a seccomp listener, instead of parking a thread on it. Accept
  loops back off on `EMFILE` and other temporary errors instead of exiting.
  The agent's control socket is `0600`.

## Behavior changes you may notice

These come from an external review on 2026-10-28
([report](https://github.com/archcorsair/drawbridge/blob/main/docs/security-audit-2026-10-28.md),
[evaluation](https://github.com/archcorsair/drawbridge/blob/main/docs/security-audit-2026-10-28-eval.md))
and the release checks that followed it.

- **A Mac wildcard listener now counts as holding the port.** A Mac service
  on `0.0.0.0:P` or dual-stack `[::]:P` was not seen as holding `P`. On XNU
  the mirror's own `127.0.0.1:P` bind succeeds beside it, so a guest loopback
  bind was allowed, and the mirror took the Mac service's loopback traffic. A
  guest wildcard bind failed, but still held Mac `127.0.0.1:P` for the 10 s
  reservation. Both now get `EADDRINUSE`. The agent answers from its synced
  copy of the Mac's ports without a round trip, and the daemon re-reads the
  Mac's listeners before it reserves or mirrors. A v6-only `[::]` listener is
  no longer synced to the guest as `0.0.0.0`. When the daemon cannot read the
  Mac's listeners at all (an unprivileged daemon on the macOS 27 betas; see
  the README), the backstop falls back to the bind result as before.
- **A transport secret that disappears now refuses connections.** Both sides
  re-read the secret per connection. A file deleted after the daemon or agent
  had loaded it used to turn every connection into `auth=0`, and the root
  daemon would then accept any local process holding its dial address as its
  agent. Now, once a process has seen the file or was given `-secret-file`,
  its absence is a refusal whose remedy is `drawbridge up <vm>`. Replacing
  the file (rotation) still takes effect without a restart. A process that
  never had a secret stays unauthenticated, as before. Details:
  [docs/transport-auth.md](https://github.com/archcorsair/drawbridge/blob/main/docs/transport-auth.md).
- **The bind-probe socket is root-only, and OCI handoffs are never refused
  for capacity.** `/run/drawbridge-notify.sock`, the 1-byte probe socket
  `bindprobe` uses, was `0666` and is now `0600` root. The agent flag
  `-notify-sock-unprivileged` restores `0666` for tests and smoke legs, and
  `drawbridge up` never sets it. Probe handoffs are capped at 4096. A
  listener that is already supervised is refused, and a handoff must arrive
  within 2 s. Handoffs from runc or crun on `/run/drawbridge-oci.sock` have no
  cap and are never closed: that fd is the container's only listener
  reference, and closing it would turn the container's `bind()` into `ENOSYS`
  for life.
- **The root daemon falls back to `127.0.0.1:4777` only for Lima targets.**
  That address is a Lima instance's SSH forward. A colima daemon with no
  usable DHCP lease (colima stopped, for example) used to dial it and reach
  the Lima VM's agent, where only a secret mismatch stopped it. A colima
  target with nothing to dial is now reported unreachable, with the
  resolver's reason in doctor check 4 and the TUI, and retried. A podman
  target keeps its pinned endpoint. drawbridged no longer exits at boot when
  a colima target resolves to nothing.
- **`up` prints a VM spelling that `install` reads back as the same VM.**
  `drawbridge up colima`, `up default` or `up <podman machine>` printed an
  install hint with the bare name, which install parses as a Lima instance.
  The resulting daemon then exited at boot on a secret file nothing had
  written. Bare names are now printed only for Lima; other providers print
  `provider:name` (colima's default profile prints `colima:colima`, the same
  VM as `colima:default`). install's missing-secret warning now says the
  daemon will not start until `drawbridge up` writes the file. It used to
  claim the daemon would run unauthenticated.
- **Rootless podman: the API-service restart now runs.** On `up --oci` and
  `down`, the restart script rendered the systemd manager unquoted, so on a
  rootless machine the restart never ran and was reported as
  `drawbridge-podman=absent`. While `podman.service` was running (Podman
  Desktop, compose, or the Mac `podman` CLI, which talks to it), containers
  kept the cached real crun and bypassed the wrapper. After `down`, creates
  failed until the service was restarted. The failure remedy now names the
  manager actually targeted. If you ran `up --oci` on a rootless machine with
  v0.2.0 and have not restarted the machine since, run this once in the
  guest: `systemctl --user reset-failed podman.service && systemctl --user restart podman.service`.
- **The guest kernel floor is checked before anything is installed.** The
  agent needs `getsockopt(SO_NETNS_COOKIE)` for the gateway, and ftrace direct
  calls (`CONFIG_DYNAMIC_FTRACE_WITH_DIRECT_CALLS`) for the listener
  tracker's fentry/fexit hooks. In practice: x86_64 needs Linux 5.14 or later,
  or a 5.12/5.13 stable kernel with the cookie backport; arm64, which is
  every Apple silicon VM, needs 6.4 or later. `up` runs the new agent's
  `features` probe on the staged binary before it installs it, and refuses
  with the reason and a remedy, leaving the installed agent untouched. Doctor
  check 2 asks the same questions of the installed agent. Ubuntu 22.04's GA
  arm64 kernel (5.15) is refused with that explanation; its HWE kernel
  (`linux-generic-hwe-22.04`, 6.8) is fine, as are Ubuntu 24.04 and Fedora
  CoreOS. Before this, an unsupported kernel showed up only as an agent
  failing at start. When the probe cannot run, a version compare decides, and
  5.12/5.13 warns rather than refuses.
- **Every upgrade remedy names the VM.** doctor's and the TUI's install
  remedies spell `-vm <installed VM>`. The TUI's skew remedy moved to its own
  `upgrade` line in the daemon box, so the command is never clipped. Root
  `sudo drawbridge doctor` now diagnoses the installed daemon's VM instead of
  `lima:drawbridge`. The agent-skew remedy mentions the `--oci` wrapper that
  `up` now refreshes.

## Under the hood

- Release binaries are built with go1.26.10 (pinned in `release.yml` and
  `mise.toml`) and `-trimpath`. v0.2.0's binaries came from go1.25.0, which
  govulncheck found reachable by 35 to 36 standard-library advisories.
  govulncheck on go1.26.10 reports none reachable for `GOOS=darwin` or
  `GOOS=linux`. `go.mod` keeps `go 1.25.0` as the minimum for building from
  source.
- Two new CI jobs: govulncheck for darwin and linux, which fails on any
  reachable finding, and a BPF regeneration job, which rebuilds the bpf2go
  output on the runner and fails on any diff from the committed objects.

Alpha. No stability promise: the wire protocol, CLI flags and on-disk state
can still change.
