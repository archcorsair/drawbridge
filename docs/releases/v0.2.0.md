## Podman machine + crun

drawbridge attaches to a Podman machine now, with the same three commands and
the same three semantics it has had for Lima and Colima. Verified end to end
on both macOS providers (`libkrun`, podman 6's default, and `applehv`),
rootless and rootful, against podman 6.0.2 with the bundled gvproxy v0.8.9.

```sh
podman machine init --rootful --now mymachine
drawbridge up podman:mymachine --oci
sudo drawbridge install -vm podman:mymachine
```

`podman run --network host nginx` in the guest then serves
`http://localhost:80` on the Mac, a guest connect to `127.0.0.1:5432` reaches
the Mac's Postgres, and a container bind onto a port the Mac already holds
fails with `EADDRINUSE` on the spot.

The recipe the support was verified with is
[docs/verify-podman.md](https://github.com/archcorsair/drawbridge/blob/main/docs/verify-podman.md);
the design and every decision behind it are in
[docs/podman.md](https://github.com/archcorsair/drawbridge/blob/main/docs/podman.md).

### How the podman path differs, in three facts

**The transport is a loopback port the guest publishes.** A podman machine
has no host-dialable guest IP (gvproxy is user-mode), and on macOS podman
starts gvproxy with no host-side control socket at all. So the guest agent
posts its own forward to gvproxy's in-guest API at every start, which is what
brings it back after `podman machine stop`, and the Mac dials
`tcp://127.0.0.1:<port>`. `drawbridge up` chooses that port once and records
it; `drawbridge doctor` reports the source as `gvproxy-publish` and grades it
`ok`, because it is the only path this provider has rather than a fallback.

**`:80` needs `--rootful`.** On a rootless machine the guest kernel refuses a
container bind below `net.ipv4.ip_unprivileged_port_start` (1024 on Fedora
CoreOS) before drawbridge is involved. Everything at `:8080` and above works
rootless, including containerized bind arbitration, and doctor names the two
ways out.

**`--oci` on podman writes one file on your Mac.** Podman mounts your
`~/.config/containers` into every machine as `/etc/containers`, so the
`containers.conf.d/50-drawbridge.conf` drop-in that registers the wrapper is
shared by every podman machine you have, and `drawbridge down` on any one of
them removes it for all. That is harmless by construction, because the
drop-in names the real `crun` as its fallback, and both `up` and `doctor` say
it out loud.

## Fixes that affect every provider

**Off-thread container binds were not arbitrated.** A seccomp notification
carries the TID of the thread that called `bind`, and `pidfd_open` refuses a
non-leader TID, so a bind issued from any thread but the main one silently
degraded to "let it through": no synchronous `EADDRINUSE`, and one line in
the agent log. Go servers and worker pools hit this intermittently, on Lima
and Colima as much as on podman. **Upgrading is recommended for that reason
alone**, and `drawbridge up <vm>` re-pushes the fixed agent.

**The daemon no longer mirrors the guest's own transport listener.** It
excluded the port the Mac dials, which on Lima and Colima is also the port
the agent listens on, but on podman is not. On Lima the stray mirror lost a
bind race to the SSH forward and was invisible; it is gone either way.

**The default skip-list is now `22,323`.** chrony's command port joins SSH:
every podman machine guest binds udp/323 and nothing on the Mac dials it.
`-skip` replaces the list as before, and `-skip ""` still skips nothing. If
you relied on `:323` being mirrored, pass `-skip 22`.

## Other user-visible changes

- **`drawbridge doctor` speaks podman** across six checks, with the catalog
  numbering unchanged and Lima and Colima output byte-identical. New states
  it reports: an agent that is up but has not published its forward, a per-VM
  record that no longer matches the machine (naming the field that moved),
  and the shared `--oci` drop-in with the machines that read it.
- **`drawbridge install` prints the VM it is replacing.** There is one
  LaunchDaemon label, so installing for a new VM replaces the old one and
  stops its sessions. That has always been true; now it is said.
- **`drawbridge install -vm podman:NAME` refuses a stale record**, naming
  which recorded fact the machine no longer matches. The ssh port is the
  sharp one: it is assigned at `podman machine init`, so a new one means the
  machine was recreated and the recorded endpoint stopped meaning anything.
- **`just smoke-sudo VM` and `just smoke-sudo-oci VM`** are the one-command
  root acceptance runs: install the freshly built daemon, prove the three
  semantics through it, run `sudo drawbridge doctor` and assert no failing
  check, then restore whatever daemon was installed before. One password
  prompt, one JSON document on stdout.
- **The Homebrew cask works on Homebrew 6.0.16 and newer**, which deprecated
  the `postflight` stanza the cask used to strip quarantine. The cask now
  emits a `postflight_steps` branch for new brews and keeps the old block for
  older ones.

## Upgrading

```sh
brew upgrade archcorsair/drawbridge/drawbridge
drawbridge up <vm>                    # re-pushes the agent: the seccomp fix is guest-side
sudo drawbridge install -vm <vm>      # the daemon binary is copied at install time
```

The second and third commands are not optional after a cask upgrade: the
guest agent and the installed daemon are both copies, and `drawbridge doctor`
reports the skew if you skip them.

Alpha. No stability promise: the wire protocol, CLI flags and on-disk state
can still change.
