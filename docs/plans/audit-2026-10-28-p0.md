## P0-1: H2, `up` echoes a VM spelling that `install` reads as a different VM

**Problem.** `pickInstance` overwrites the canonical `ref.Spec` with the user's
bare spelling ([guest.go:308](../../cmd/drawbridge/guest.go)). `up` prints it
in the install and foreground-daemon hints ([up.go:799-800](../../cmd/drawbridge/up.go)),
and `install`/`drawbridged` re-parse it with `ParseRef`, where a bare name is
always Lima. `colima` becomes `lima:colima`, `default` becomes `lima:default`,
podman `spike` becomes `lima:spike`; the daemon then fatals on a secret file
nothing writes.

**Change.** Echo a spelling that round-trips: bare only for Lima instances,
`provider:name` otherwise. Add a vmprovider-level invariant test that
`ParseRef(r.Spec)` yields the same provider and instance as `r` for every
provider's refs. Correct install's missing-secret warning, which says the
daemon "will run UNAUTHENTICATED … no reinstall needed" when it actually exits
fatally (`cmd/drawbridged/main.go` secret boot path).

**Verify.** Unit tests for `colima`, `default` (colima), a podman machine and a
Lima instance through `pickInstance` → printed line → `ParseRef`. Built CLI:
`drawbridge install -vm <echoed> -print` renders the secret path `up` writes.

## P0-2: H1 + NEW-A1, a Mac wildcard holder is not seen as taken

**Decision E1: both layers.**

**Problem.** The `'R'` reservation and the async mirror decide "the Mac holds
P" only from their own `net.Listen("tcp", "127.0.0.1:P")`, which succeeds on
XNU beside a `0.0.0.0:P` or dual-stack `[::]:P` holder and then wins
`127.0.0.1` connects ([mirror.go:662](../../internal/mirror/mirror.go),
[:480](../../internal/mirror/mirror.go)). A guest loopback bind is allowed and
takes over the Mac service's loopback traffic. A guest wildcard bind fails
natively but still holds Mac `127.0.0.1:P` for the 10 s reservation and
withdraws P from the guest (NEW-A1).

**Change.**

1. Guest: before asking the Mac, `ReservePort` answers `inuse` when the port is
   already in the agent's synced Mac-port set (`mac_ports`): no round trip,
   no reservation. This alone removes NEW-A1 for synced ports.
2. Mac backstop for unsynced ports (skip list, filtered enumeration):
   `handleReserve` and the async mirror open take a fresh listener read and
   answer `inuse` / record `bind-failed` when any socket holds P on `0.0.0.0`
   or dual-stack `::`. The pcb parser must keep `inp_vflag`
   (`INP_IPV4` = 0x1) so v6-only `::` is not counted; fix L23 with the same
   field. An empty enumeration is "unknown", never "free" (AGENTS.md 27.0b4
   note).
3. Keep `SO_REUSEADDR`; clearing it is the rejected fix.
4. e2e leg with a wildcard Mac holder (dual-stack `[::]` and `0.0.0.0`) for
   both a guest loopback bind (expect `EADDRINUSE`) and a guest wildcard bind
   (expect `EADDRINUSE` and no reservation logged).

## P0-3: H3 (+ M15, M11, M22, R1, I6, NEW-D1 text), upgrade remedies re-target the root daemon

**Decision E3: inherit and print.**

**Problem.** `install`'s `-vm` defaults to `drawbridge` and nothing fills an
omitted flag from the installed plist, so the documented upgrade
(`sudo drawbridge install`, in 20+ places, worst
[render.go:84](../../cmd/drawbridge/render.go)) re-targets the daemon, and a
re-install with only `-vm` drops `-vm-mac`, `-vm-subnet`, `-udp`, `-skip`
(M15). Positional arguments are silently ignored (M11). Root doctor diagnoses
the default VM instead of the installed one (M22).

**Change.** Every flag not set explicitly (`flag.Visit`) defaults from the
installed plist, and install prints each inherited value; an explicit flag,
including `""`, overrides. Accept a positional VM the way `up`/`down` do and
reject leftover arguments in install, uninstall, status, doctor and tui.
Remedies that name an install target render `-vm <installed>` where the VM is
known; a bare `sudo drawbridge install` is now a correct upgrade, so static
text (cask caveat, README) may stay bare but must say it keeps the installed
settings. Root doctor defaults to the installed VM. Fix doctor.md check 6's
tier-2 remedy (R1) and the "replacing" notice (I6, compare canonical refs).

## P0-8: NEW-X1 (E5), the root daemon dials any VM on 127.0.0.1:4777

**Decision E5: Lima-only fallback.**

**Problem.** For a colima or podman target with no lease or pin, resolution
falls back to Mac `127.0.0.1:4777`
([limaaddr.go:163](../../internal/limaaddr/limaaddr.go)), which is the Lima
dev VM's SSH forward on this Mac. Seen live: the installed `colima:default`
daemon dials the dev VM's agent; only the secret mismatch refuses it.

**Change.** Only a Lima target may fall back to `127.0.0.1:4777`. A colima
target with no usable lease reports the guest unreachable with the resolver's
note and retries on the normal cadence; podman keeps its pinned endpoint.
doctor and the introspection resolution note say why.

## P0-4: M6 + NEW-A2, a secret that vanishes at runtime downgrades auth to none

**Problem.** `MacConfig.Secret` re-reads the file per dial and
`LoadOptional` folds "absent" into nil, so `ClientHello` sends `auth=0`
([transportauth/mac.go:108](../../internal/transportauth/mac.go)). Only boot
treats a missing explicit `-secret-file` as fatal. The guest agent has the same
fold per accepted conn ([agent/transport.go:83](../../internal/agent/transport.go)).
This violates AGENTS.md: "a configured-but-unreadable secret fails closed" and
"a side with a secret refuses unauthenticated peers".

**Change.** Once a secret is configured for this process (explicit flag, or a
file that was present and loaded at least once), absence is a refusal
(`CauseSecretUnreadable`) with a named remedy, on both sides. A process that
never had a secret keeps today's unauthenticated mode (audit #26, by design).
Rotation that replaces the file keeps healing live.

**Verify.** Unit tests on both sides: loaded then deleted → refusal, never
`auth=0`; replaced → new secret used; never configured → unauthenticated as
today. Guest leg: needs guest run.

## P0-5: M3 (+ L14), any guest process can fill the supervision cap

**Decision E2: OCI exempt, probe socket locked.**

**Problem.** One 4096-slot cap is shared by the `0666` probe socket and the
`0600` OCI socket, counts fds rather than senders, and closes the fd on
refusal ([notify.go:105](../../internal/agent/notify.go),
[notifycap.go:18](../../internal/agent/notifycap.go)). For an OCI handoff that
fd is the container's only listener reference, so its `bind()` becomes
`ENOSYS` for life. Any unprivileged guest process fills the cap by re-sending
one listener 4096 times (reproduced; ~4096 OS threads remain afterwards). The
probe-socket handoff read has no deadline (L14).

**Change.** OCI-socket handoffs are never refused and never closed for
capacity; they are supervised under their own accounting. The probe socket
is `0600` root-owned in production; tests and smoke legs opt back into a
wider mode with an explicit agent flag. Probe handoffs keep a cap, dedupe by
file identity (`kcmp(KCMP_FILE)`; all seccomp listeners share one anon inode),
and get a 1 to 2 s read deadline. The OCI socket's unbounded `io.ReadAll`
gets a size limit and deadline that do not break runc's protocol. Keep "the
supervisor must always answer" and poll-first supervision.

## P0-6: M13, the documented upgrade never refreshes the OCI wrapper

**Problem.** `up` pushes the runc/crun wrapper only under `--oci`
([up.go:108-113, 168](../../cmd/drawbridge/up.go)), while the cask caveat,
README and doctor tell users to upgrade with a plain `drawbridge up <vm>`. A
guest provisioned with `--oci` keeps the old wrapper, which still overwrites an
existing `listenerPath`: audit #5's deny-becomes-allow survives the upgrade
meant to fix it. No release contains PR #1 yet, so this blocks the next one.

**Change.** A plain `up` refreshes the wrapper whenever the guest is already
provisioned with `--oci` (`/etc/drawbridge/provision.json` present for either
engine, or the wrapper path exists), pushing only when the digest differs, with
the same atomic install `--oci` uses. A plain `up` never newly registers a
runtime. Update the upgrade text (cask caveat, README, release notes, doctor)
that says the upgrade touches "three parts" so it covers the wrapper.

**Verify.** Fake-guest unit tests: provisioned guest with a stale wrapper →
plain `up` replaces it; unprovisioned guest → plain `up` pushes nothing; same
digest → no write. Guest leg: needs guest run.

## P0-7: M9, the rootless podman API-service restart never runs

**Problem.** The restart script renders `SC=%s` unquoted
([ocipodman.go:187](../../cmd/drawbridge/ocipodman.go)), so
`SC=systemctl --user -M core@.host` becomes an env-prefixed command named
`--user`, `SC` stays empty, and the script reports
`drawbridge-podman=absent`. `up_test.go:592` asserts the buggy line, and the
fake guest never executes the script (NEW-E3). The failure remedy also always
names `systemctl --user`, wrong on a rootful machine (L40).

**Change.** Render the manager so it survives a POSIX shell; print the remedy
for the manager actually targeted. Add a test that executes every rendered
variant (rootful, rootless) under `/bin/sh` with a stub `systemctl` on PATH and
asserts the argv it received.

**Verify.** The new execution test fails on the old template and passes on the
new one.
